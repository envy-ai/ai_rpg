# RuntimeReviewedSetup

Generic reviewed New Game orchestrator used by a registry draft provider. Existing goal-only/New Game requests retain their ordinary behavior. Explicit token Start resolves reviewed fields/source fingerprints inside the replacement barrier. The first attempt cancels prior work and reuses extracted canonical reset, world calendar/time setup, skill/faction generators, protagonist setup, region/location generators, discovery, inventory/abilities and intro.

Successful stages record actual generation/player/region/location identities through provider.stage. Retries verify the same runtime generation/profile and skip completed stages; they do not reset or replace the runtime again. Player binding callback runs before starting region/intro, so mod generation/context contributors see approved opening direction in standard and TinyBrain paths. Setup completion checks actual player/location and real game-intro evidence; ability-selection deferral retains provider token and reports awaiting-intro until canonical selection produces the opening. Failures retain original stack and partial receipts.

The draft provider maintains canonical identity checkpoints before receipt persistence. If recording a just-created protagonist fails, its Player namespace and owned runtime stage record retain the actual identity/binding; explicit resume verifies the same runtime/profile/registered actor and persists that checkpoint before continuing. It never creates another actor to conceal a failed receipt write. Successful profile saves likewise retain their actual profile identity for same-request retry. Missing or mismatched runtime identities raise an explicit reconciliation error.
