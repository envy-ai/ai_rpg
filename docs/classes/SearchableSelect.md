# SearchableSelect

Search and select controls inherit the containing UI's font through the shared
SCSS rules. Callers compose their existing surface, border and text styles with
the widget; technique cards use the shared modal theme and visible focus outline.

The portable implementation is
[`packages/ui-widgets/src/searchable-select.js`](../../packages/ui-widgets/src/searchable-select.js),
exported from the package's ESM entry without application globals or dependencies.
[`client/widget-adapters/searchable-select.js`](../../client/widget-adapters/searchable-select.js)
preserves `window.AIRPG_WIDGETS.SearchableSelect` for current classic-script consumers.
`public/js/widgets/searchable-select.js` is generated by `npm run widgets:build`;
edit the package/adapter source rather than the generated browser asset.
The New Game class selector is an ordinary HTML `select`; this widget uses
the same native control for single selections and checkboxes for multiple
selections, with a separate search input above either presentation.

Construct it with an `HTMLElement` root and
`{ multiple = false, options = [], value = null, onChange = null,
emptyLabel = 'Use workflow default' }`.
Options are distinct, trimmed, nonblank strings. `data-label` on the root
provides the accessible control name; `data-placeholder` supplies the search
placeholder. `getValue()` returns a string or a copied array according to
`multiple`. `setValue(value)` and `setOptions(options)` rerender without
emitting a user change. User selection invokes `onChange(value)` and emits
the bubbling `searchable-select-change` event with `detail: { value }`.

Search is case insensitive and splits on whitespace. Every substring must
occur in an option, in any order: `qwen fp8` matches a filename containing
both strings. Search preserves the selected value, including when nothing
matches. A single selected value stays displayed when filtered out; a stored
value absent from the available options is labeled `(unavailable)` until
changed. The blank **Use workflow default** option clears a single choice.
`emptyLabel` customizes that blank label for reusable non-workflow contexts;
TechniquesPanel uses **Choose…** and **Choose target…**.
Native selection retains the browser's mouse and keyboard behavior. Disabled
state survives rerendering and checkbox filtering.

Large option lists cache lowercase search text and available-name membership
when constructed or updated through `setOptions`. Filtering checks each cached
name once per query rather than lowercasing it for every search term or scanning
the full available list for each result. Both native options and checkbox rows
are assembled in a detached document fragment and replace the connected list
in one operation. All matching options remain available immediately; filtering
does not impose a result limit or change selection/persistence semantics.

`setDisabled(boolean)` updates the generated controls and `disabled` exposes the
current state. Workflow inheritance uses this explicit API alongside disabling its
other fields. Direct host disabling of the search input still survives rerenders,
preserving existing pending-form behavior. Idempotent `destroy()` removes generated
controls/listeners and releases root/callback references. A new instance can remount
the root; other methods/getters reject use after destruction. DOM/events are created
through the root's document, including iframe roots.

The generated search, select, and checkbox controls have no form names.
The host owns persistence through `getValue()`/`onChange`; the workflow editor
serializes its hidden workflow JSON. LoRA availability reconciliation belongs
to that editor, rather than this general widget, so filtering never deletes
selections.

Generic styles are authoritative in `packages/ui-widgets/styles/` and included by
`public/css/main.scss` at their original cascade position. Workflow and technique
themes remain in app SCSS. The portable default empty label is **Choose…**; the app
adapter preserves **Use workflow default**. See the
[package README](../../packages/ui-widgets/README.md) for independent ESM/SCSS use,
builds, lifecycle and the standalone specimen. The workflow editor composes its
**Add LoRA** single-choice selector with the registered `Repeater` to edit an
ordered table of name/strength rows. It excludes already-selected names from add
choices; availability reconciliation and per-row strength persistence remain
workflow-owned. The shared workflow macro is
`views/_includes/image-workflow-editor.njk`, used by System Configuration and
World Profiles. Browser interaction coverage lives in
`tests/e2e/image-workflow-loras.spec.js`.
