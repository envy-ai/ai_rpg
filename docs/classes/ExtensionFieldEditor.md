# ExtensionFieldEditor

`public/js/extension-field-editor.js` owns native scalar controls for registered Thing/NPC mod extension descriptors. It composes `AIRPG_WIDGETS.createField`; descriptor registration, persistence namespaces, special module fields and modal transactions remain application adapters. Play loads the controls adapter and this script before evaluating its inline form owners.

`new ExtensionFieldEditor(root, {idPrefix, inputClass, inputTypeFor, getValue})` adopts a field container. `inputTypeFor(descriptor)` chooses `text`, `textarea`, `number` or `checkbox`; `getValue(record, descriptor)` defaults to reading the descriptor's field name. Thing supplies its existing top-level-before-metadata lookup. Thing and NPC retain their different default native input types. An undefined stored value uses `defaultValue`; explicit null does not.

`render(descriptors, record, {createSpecial})` rejects duplicate/empty field names, clears previous owned controls and renders visible labels, original IDs/classes, placeholders and help. `createSpecial(descriptor, record)` may return a same-document element for an application-owned editor, or nullish to use the scalar control. The module adapter retains slot-type rules and its own collector. Special fields are excluded from scalar collection.

`collect()` reads only the current owned scalar inputs. Booleans retain false; populated numeric fields must be finite, and integer descriptors require integers. Blank nonboolean fields return null, while explicit zero, empty arrays and empty objects remain distinct. Array/object JSON errors retain their cause and identify the field and correction. Removed owned inputs reject rather than silently dropping a property. `formatValue` and `readValue` expose the same scalar conversion rules for focused use.

`clear()` releases nested ReaderRows owners and replaces transient controls while retaining the reusable editor. `destroy()` is idempotent and releases its references; subsequent use requires a new instance. Persistent Thing/NPC modal owners reuse the editor through clear/render. Persistent Add buttons for adjacent metadata/ability lists retain live ReaderRows owners through clear, rather than caching destroyed owners.

Metadata rows intentionally retain their separate text-or-JSON serializer. Ability rows retain IDs, image identity, attachments, field validation and existing numeric policies. These domain rules are not scalar mod descriptor behavior. Focused Chromium coverage exercises typed values/errors directly and through real Thing/NPC save/reopen, persistent Add/Remove and desktop/phone geometry; separate module cases verify malformed configuration and unavailable IDs. See the [form consolidation plan](../superpowers/plans/2026-11-05-form-field-consolidation.md) for exact boundaries and evidence.
