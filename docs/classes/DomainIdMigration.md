# DomainIdMigration

`DomainIdMigration.prepare(snapshot)` prepares the explicitly requested running-world ID migration as `{ serialized, counts, replacements }`. `counts` is a flat prefix-to-number map of changed canonical identities; `replacements` maps old canonical IDs/aliases to new IDs. Preparation clones its input, uses the shared allocator in a synchronous isolated state, and restores every live allocator store even when validation throws. It neither installs the candidate nor writes a save.

The collector visits all 17 shared-domain categories, map-key aliases, nested quests/objectives, intrinsic/ability/thing cause statuses, explicit grants, owned/declined/pending abilities and attachment drafts, pending quest offers, pending regions, catalogue definitions/disciplines and named receipt-only status records. Source text follows [IdGenerator](IdGenerator.md). Different categories sharing an exact old ID reject because their references would be ambiguous. Descriptive templates without IDs are not invented into canonical records. Historical removed actors/targets retain unknown IDs when no named record exists.

Existing IDs already equal to their current source's `prefix_first_three_words` stem, optionally followed by a canonical integer suffix of at least 2, remain unchanged. All existing IDs and persisted counters reserve before replacements allocate. Repeating migration against the same candidate therefore preserves its identities and counters.

Exact reference strings and map keys transform simultaneously, with collision checks. Protected prose/name/history text, operational operation/turn/chat IDs, image IDs/filenames, world lineage and allocator metadata remain unchanged. Known derived identities transform semantically: `learned:<technique>`, `status_grant:<status>:<index>`, `status:<actor>:<grant>`, equipment-derived status/grant identities, and receipt effect mutation IDs. Party-member and route-knowledge quest benefit IDs/applied receipts transform with their actor/location/exit references. Canonical actor/status/ability/item references inside provenance, receipts, metadata and image target descriptors transform with the map, including compound actor/ability image targets. The prepared technique graph is validated with the prepared actors/things before return.

Bound Story snapshots reject before installation: independent library bindings/receipts cannot be safely rewritten by a world-only migration. There are no sidecar writes or silent partial migrations.

The slash-command runtime wrapper owns cancellation/replacement locking, the recoverable original backup, native hydration, preservation checks, rollback, pending confirmation restoration and client refresh. Strict `Utils.hydrateGameState(..., { preserveRuntimeSnapshot: true })` propagates hydration errors and skips ordinary pending-region repair/merging. Saved audit times can be restored through `Location.restoreSavedTimestamps` and `LocationExit.restoreSavedTimestamps` after graph setters finish. Ordinary load behavior retains its existing repair policy.

Tests cover input/allocator purity, all identity categories, exact references/map keys, protected text, numeric/name collisions and idempotence, compound sources and receipts, ambiguity/unsupported binding errors, and runtime preservation/rollback. Implementation tests do not execute the command on the user's live game.
