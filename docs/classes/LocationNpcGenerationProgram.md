# LocationNpcGenerationProgram

`runLocationNpcGenerationProgram(...)` uses the native [TinyBrainPromptRunner](TinyBrainPromptRunner.md) for `location_npc_generation`. The original location-generation user prompt is a fixed prefix, followed by the runner's program marker and one staged suffix. The suffix carries the accepted location proposal and nearby-location context once; it does not duplicate the large base context. The first checkpoint requests a compact XML roster. One checkpoint then expands each approved NPC profile, with its own named schema, strict [plan/checkpoint parser](LocationNpcGenerationPlan.md), and configured `ai.retryAttempts + 1` correction attempts. Rejected text and exact parser errors stay in the runner's correction conversation and log. The roster schema applies only to planning; the single-NPC schema applies only to expansion. No native tools are exposed.

The terminal result builder assembles the accepted per-NPC XML locally, with no extra model completion. The caller receives the existing `{ response, value: { npcs, memories } }` shape and then follows the original naming, skills, abilities, inventories, equipment, quantity expansion, technique initialization and registration path. All staged XML and construction checks finish before that path starts, so a later invalid NPC cannot cause an earlier planned NPC to be registered. The downstream NPC followups and registration retain their existing incremental error/commit boundary.

`ai.tinybrain_prompts.location_npc_generation` routes this family under the effective `location_npc_generation` model configuration. When disabled, the existing one-shot full-batch prompt and parser retry remain in use. The existing zero-total generation-hint early return also remains in force. Queue reservation, progress, cancellation, failure reporting and logging are owned by the native runner; this program does not start a server, load saves, or change retry budgets.
