# TinyBrainPromptParsers

`TinyBrainPromptParsers.js` contains side-effect-free parsers for staged prompt checkpoints and final responses. Every returned value is JSON-serializable so `TinyBrainPromptRunner` can retain it in render state without carrying DOM nodes or game objects. XML parsers accept a single final complete XML block surrounded by commentary or an `xml` Markdown fence, then return the extracted XML as `normalizedResponse`; malformed or ambiguous mechanical content still fails.

Generic parsers cover revision decisions, allowlisted character selections, narrative travel scope, exact XML roots, and exact outcome acknowledgements. Exact-root checkpoints reject empty roots by default and accept them only through the explicit `allowEmptyRoot` option; while-away arrivals and item/scenery moves enable that option because their prompts require empty roots when nothing changed. Outcome acknowledgements require the complete exact fact multiset but permit harmless fact reordering. Domain parsers validate quest-reward coverage, game-intro XML, turn/move prose, craft/location results, checked-container results, while-away updates, scheduled-event results, and scheduled-event interruption rewrites.

The need-bar characters parser accepts XML-only `<characters>` results, permits an empty root when no bar changed, and validates every affected-character block. It rejects unknown configured need-bar ids, duplicate characters or bars, missing fields, invalid direction/magnitude keywords, directionally impossible `decrease/full` or `increase/empty` pairs, and unexpected elements. The harmless structured aliases `fill` and `drain` normalize to canonical `full` and `empty`, respectively. The prompt still asks for reasons of ten words or fewer to discourage paragraphs, but reason length is not parser-enforced and cannot fail a turn.

The TinyBrain player-action terminal uses compact non-XML parsers for movement, state-dependent vehicle decisions, prose scopes, location/region destinations, destination-change planning, checked-action actors, exact durations, accompanying characters, required prose, optional hidden notes, and time reasoning. Unambiguous choice answers tolerate `Answer:`, outer emphasis, and trailing sentence punctuation. The destination lookup checkpoint uses `parsePlayerActionMoreInfoOrNa()`: it accepts exact `N/A`/`NA` only when the current checkpoint made no successful tool call, and accepts exact `READY` only after at least one successful current-checkpoint `moreInfo` call. It rejects prose, other tools, failed `moreInfo` calls, `READY` without a lookup, and `N/A` after a lookup, so a model cannot narrate the destination instead of supplying lookup context. Prose scopes accept commas, semicolons, newlines, or `and`, canonicalize their order, and deduplicate repeated choices. Destination lines may be ordered either way and may use Markdown bullets. Revisit-change planning accepts exact `NONE`/`N/A` or a Markdown bullet list; it rejects headings, surrounding prose, numbered lists, XML, mixed sentinels, empty bullets, and normalized duplicate bullets. The prompt requests brevity, but the parser deliberately does not enforce a character limit. Checked-action actors and accompanying characters share exact canonical-name/alias selection rules and return canonical names; `NONE` is accepted when no eligible actor applies. Partial names, unknown identifiers, ambiguous identifiers, duplicate selections, and selecting one actor through both name and alias remain errors. Duration parsing reuses `Utils.parseDurationToMinutes()` and validates minimum/integer constraints without clamping. Prose and hidden-note parsers reject old result wrappers so the model cannot bypass the staged control flow.

The higher-risk parsers enforce cross-stage invariants:

- quest reward coverage must have every original index exactly once and can be checked against the original reward strings;
- craft and location-modification output must resolve to the mechanically selected duration, while equivalent duration wording is accepted;
- a container final must correspond to exactly one successful check-tool invocation, name that tool, agree with its authoritative success value, prevent permanent opening on failure, and contain a parseable duration;
- each while-away candidate checkpoint must use the candidate's exact name and canonical `<name>`, `<needBarChanges>`, optional structured `<travelDestination>`, and required `<update>` fields; need-bar values must be `N/A` or percentages from 0 through 100. Arrival checkpoints additionally require literal `HERE`. The combined final validator accepts that exact text sentinel alongside ordinary structured destinations, but rejects arbitrary text and mixed text-plus-child destinations. It also rejects nested structured wrappers or changes to staged character updates, arrivals, or item/scenery moves, while permitting harmless reordering of character and item/scenery entries;
- a scheduled-event final must preserve its approved hidden summary and omit player prose for offscreen events;
- an interruption rewrite may change player-facing prose fields only; its root, hidden notes, time data, travel destinations, vehicle data, and every other non-prose XML field must remain equivalent.

Malformed XML, duplicate/unknown values, missing required fields, and invariant drift throw descriptive parser errors. The runner retries the same checkpoint without applying domain mutations. TinyBrain API integrations run their downstream XML/value parsers from the retryable final-parser callback before accepting game-intro, random/NPC action, creative-action, while-away, scheduled-event, and checked-container results. The remaining semantic hardening backlog and the explicit decision to skip heuristic prose-to-fact validation are recorded in `docs/tinybrain_parser_hardening.md`.
