# OperationalIdMigration

`migrateOperationalIds(snapshot)` extends the detached current-loaded-game `/migrate_ids` candidate with UUID-backed operational identities. It returns `{serialized,counts,replacements}` and never installs game state. Canonical chat IDs are collected first: an optimistic user chat row and its matching request UUID map to one `chat_N`. Generated-image registry identities, quest offers, receipt operations, turns, requests, arrivals and world lineage follow. Known references/map keys, receipt mutation keys, `techniqueRecordId` use/change keys, evidence and accepted XML receipt leaves map together. Prose, filenames/URLs, provider IDs and unrelated library/save files are not rewritten.

The native API capture resolves actual existing UUID-image filename/URL metadata before replacing IDs, using the existing image resolver rules without changing live metadata or renaming an asset. Detached migration rejects unresolved minimal image metadata rather than inventing a path. The migrated image registry therefore continues to resolve the original files through normal server/API image helpers.

Item charge dedupe hashes consume original event source scopes. When a saved replay pass source ID changes, its original scope is retained as server-only `pass.options.chargeEventScope`; native scope validation and reprocessing forward that exact provenance, including deterministic nested followups. Canonical source/evidence references change while these historical opaque hash inputs remain unchanged. No hash is guessed or recomputed from missing facts.

Domain UUIDs map to numeric `char_N`, `thing_N` and other existing prefixes; existing named and numeric canonical IDs remain valid, so repeats are idempotent. Preparation may consume durable sequential reservations even if validation/backup/install later aborts, leaving harmless gaps. Live registries, existing save files and historical references remain unchanged until the existing transactional installation succeeds. The backup, strict hydration, preservation checks, rollback and browser reload remain owned by [DomainIdMigrationRuntime](DomainIdMigrationRuntime.md).

Bound Story/setup games retain the explicit unsupported guard: their independent library references cannot be coherently migrated by a current-game-only command. No library migration or bulk old-save rewrite is implied. New Story IDs already use sequential categories, while historical UUIDs continue loading.

Deterministic native operation IDs keep their semantics: player/NPC technique, NPC ordinary-attack, resolution and native charged-attack cache keys map their exact canonical source/actor selectors while retaining their known structure. Only directly UUID-backed opaque editor/learn operations receive fresh whole operation IDs. Arbitrary compound/provider strings are not substring-rewritten. Persisted `techniqueRecordId` use/change keys map with receipt operations, preserving observer deduplication.

Saved housekeeping/review turn cursors and scene-summary `startEntryId`, `endEntryId` and `entryIndexMap[].entryId` follow their migrated canonical chat rows. Their timestamps, indices and prose remain unchanged.
