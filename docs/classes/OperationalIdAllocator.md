# OperationalIdAllocator

`OperationalIdAllocator.js` supplies installation-wide `category_integer` identities through `IdGenerator.nextSequential(category)`. Named domain allocation is unchanged. Operational state lives in `runtime-id-leases/`, outside save rollback and new-game resets. `AIRPG_ID_STORE_DIR` explicitly selects an independent store for tests or a separate installation; set it before any module import because some services allocate runtime identities during initialization. Docker Compose persists the default store in its `runtime_ids` volume. Do not delete this state while retaining records/assets that use its IDs.

Each exclusively created, fsynced `category.END.lease` file reserves a fixed 1024-integer range. Allocation then increments in memory; no disk operation occurs for individual audit events. Initial directory discovery happens once per allocator. Competing processes claim different aligned ranges with atomic exclusive creation. No locks, stale-lock recovery, random fallback, timestamp suffix or per-ID network call is used. Restart, crash, abandoned browser pools and rejected preparation can leave gaps; ranges from different processes can be issued out of numeric order. The contract is unique category ordinals, not contiguous wall-clock ordering.

`new OperationalIdAllocator({directory})` exposes `next(category)`, `reserve(category,count=1024)`, `register(id)` and `discardRanges()`. Reservations return `{category,start,end}` for one whole exclusive block; count must be 1–1024. `register` consumes the block containing a supplied numeric ID and advances an active local range past that identity. Invalid categories/ranges, corrupt lease names, unavailable storage, and unsafe-integer exhaustion throw. Native load discards unused local ranges before registering actual imported identities; ordinary page reload replaces browser leases. Existing game/project writers support one live game server per state root, not distributed simultaneous import into independently active leased runtimes.

[OperationalIdRegistration](OperationalIdRegistration.md) handles explicit save namespaces. [SequentialIdClient](SequentialIdClient.md) supplies server-owned browser pools. [ComfyUIClient](ComfyUIClient.md) alone retains required UUID creation at the external prompt protocol boundary. Provider-assigned identities remain opaque.
