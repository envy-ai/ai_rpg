# Quest editor

The Play quest editor in `views/index.njk:initQuestPanel` composes ReaderRows and createField for editable reward/objective rows. Quest models, normalization, API validation, option directories, identity rules and modal transactions remain application-owned.

Five persistent owners cover physical items, faction reputation, NPC dispositions, mixed typed benefits and objectives. Open/close uses clear rather than destroy, retaining static Add listeners across reopen. Native Remove buttons are owned by ReaderRows. Final non-persisted page hide destroys owners; cached page hide retains them. Actual row readers expose their current native controls/metadata to the original collectors; they do not replace quest serializers with a generic schema.

Visible labels use the existing native field primitive. Item names/descriptions retain blank-row filtering. Faction and disposition collectors retain their existing nonzero integer filtering/grouping; scalar currency/XP zero behavior remains separate. Objective description/optional/completed values and saved IDs retain the canonical `QuestObjective` contract. New IDs remain server allocated. Optional/completed are fixed flags within a free objective row, not separate condition lists.

Typed benefits retain saved benefit IDs, route source/destination identity, descriptions/roles, current-value metadata and original party-before-route collection order. Applied route identities keep their disabled select/Remove controls; canonical server validation still governs all already-applied benefits. Unknown current IDs remain explicit selected options instead of being dropped.

NPC/route rows own their change listeners and async delivery lifetime through AbortSignals. Closing/rebuilding/removing aborts delivery to that row without cancelling a directory request shared with other rows. Current NPC/route options are seeded before awaiting lookup so saving while loading preserves existing targets. At delivery, the adapter captures the live selection; clearing a route while loading stays cleared. Pinned route source/destination metadata remains explicit. Lookup failure retains the current value and surfaces the original error through page feedback; it does not manufacture a successful empty selection. One quest-scoped weak error registry reports the same shared lookup rejection once while each active row finishes its own state update. Different errors and a later deliberate failed lookup remain reportable. Private NPC/route JSON parsing preserves parse causes.

Faction lookup remains its shared adapter, including unknown-ID presentation. Removed faction rows do not open a new failure dialog. Other quest actions, reward execution, confirmation/completion/retry and shell policies remain unchanged. Focused browser cases passed edited IDs/flags/values, loading/error retention, late delivery, reopen and desktop/phone geometry; exact evidence is in the [row consolidation plan](../superpowers/plans/2026-11-05-quest-region-row-consolidation.md).
