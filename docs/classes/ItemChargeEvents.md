# ItemChargeEvents

`ItemChargeEvents.js` provides strict nested XML parsing, exact committed-reference suppression, and application through `ItemChargeService`. Standard XML, grouped event prompts and staged TinyBrain item checkpoints share it; no model JSON command leaves are accepted.

`reloadItem` contains required `actorId`, `itemId`, `ammoItemId`, `amount`. The amount is a positive integer quantity actually loaded from that exact owned compatible loose ammunition stack into the exact owned discrete pool. `chargeAdjust` contains required `actorId`, `itemId`, `amount`, `reason`; amount is the exact resulting balance (including zero), validated within capacity and pool mode. No inferred regeneration, pools, fuel conversion or detachable magazine mechanics exist. Player and registered NPC actors use identical inventory checks.

Optional `chargeReceipt` contains nonempty operationId/mutationId and may acknowledge only an exact committed operation. Mutation IDs are `operationId:reload:itemId` for loading and `operationId:charge:itemId` for adjustments/ordinary attack payments. A chargeAdjust may instead contain `techniqueReceipt` referencing `operationId:cost:charge:itemId`. References are exclusive and must match the exact event kind, actor, target, source and quantity/result; an ordinary attack’s amount is the resulting pool balance. Invalid or unrelated references raise correction errors. Only the matching mutation is suppressed; independent same-turn events remain actionable.

The engine derives event operation IDs from the native recorded source/section scope, event kind and chronological occurrence within that kind. Event results expose `itemChargeChanges` with service receipts and mutation IDs. Reprocessing uses saved operations before current actor/source lookup, so consumed ammunition is not required to still exist. Later independent prose entries have distinct operation scopes even when their requested quantities match.

`Events.runEventChecks` accepts sourceEntryId or chargeEventScope outside a current EventReprocessor pass. Nested followups retain parent identity plus a deterministic child-text identity. Missing stable scope rejects clearly; a global payload hash would suppress legitimate later reloads and is deliberately unsupported. `TechniqueEvents` delegates charge-linked event checks to this adapter while retaining its existing health/need/status behavior.

`resolveScope(context, passIdentity?)` supplies one canonical `{sourceEntryId,eventSectionKind}` shape for explicit source fields and native pass identity, normalizing section case and defaulting to current. Explicit nested chargeEventScope remains intact. Thus original extraction and replay hash identically, while origin/destination sections stay distinct.

Operation hashes exclude domain actor/item/ammunition IDs so explicit domain-ID migration preserves replay identity. The saved service request still validates every exact actor, target, source and amount after those references migrate. A different payload at an already committed event position rejects instead of paying again. Multiple identical intentional events retain separate per-kind occurrence positions.
